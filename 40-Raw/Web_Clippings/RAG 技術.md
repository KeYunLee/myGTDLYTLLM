## Agent 優化技術方案

## 概述

本文件整理了優化 RAG（檢索增強生成）檢索與跨文檔比較的技術方案，旨在提高文檔檢索的精準度與覆蓋率，並實現穩健的跨文檔比較表格生成方法。

## 一、提高文檔檢索的精準度與覆蓋率

### 1\. 優化文檔切分與嵌入策略

- **自適應切分**
	- 根據語義或段落進行合理切片，避免切片過大或過小
		- 確保每個 chunk 都圍繞單一主題，減少無關內容並提高檢索精度
		- 將文檔元數據（如標題、類別）附加到向量，利用元數據過濾來限制檢索範圍
- **嵌入模型優化**
	- 選擇高質量的嵌入模型（如 OpenAI 的 text-embedding-ada-002）
		- 針對領域術語進行微調或使用領域專用模型
		- 提升語義匹配效果，降低遺漏關鍵內容的概率

### 2\. 引入混合檢索 (Hybrid Search)

- **雙通道檢索**
	- 結合稀疏檢索（關鍵詞/BM25）與稠密檢索（向量匹配）
		- 同時捕捉精確匹配的術語和語義相關內容
		- 特別適用於技術規格或法律條款等專業文本
- **向量數據庫實現**
	- 使用向量數據庫（如 Pinecone、Weaviate、Redis 等）的 Hybrid 查詢功能
		- 確保專業術語、代號精確匹配
		- 通過語義匹配找到語義相關的段落
		- 大幅提高召回率和上下文相關性

### 3\. 增加 Top N 及分級檢索

- **分層篩選策略**
	- 適當提高初始檢索的 N 值（Top 20-30 個片段）
		- 採用更精細的相關度評估模型進行重新排序
- **二階段檢索**
	- 第一輪：用向量相似度獲取較大量的候選片段
		- 第二輪：利用重排序（Re-ranking）模型評估相關性
		- 使用跨編碼器或 GPT-4 進行精確評估
		- 採用 Maximal Marginal Relevance (MMR) 策略選擇多樣化且相關性高的片段

### 4\. 應用查詢擴展與多輪檢索

- **查詢改寫**
	- 利用已檢索的上下文片段豐富原始查詢詞彙
		- 加入同義詞、相關術語進行再次檢索
		- 使用 OpenAI GPT 模型生成查詢改寫（QOQA 方法）
- **多輪迭代**
	- 在 LangChain 中使用 Multi-step Retriever
		- 先後執行關鍵詞檢索和語義檢索
		- 根據初步回答識別尚未涵蓋的要點，觸發新一輪檢索
		- 逐步完善回答，避免一次檢索遺漏

### 5\. 向量數據庫與工具鏈優化

- **數據庫調優**
	- 選擇性能優秀的向量數據庫
		- 調優索引參數（如 HNSW 索引的 ef 搜索參數）
		- 在可接受延遲內提高召回率
- **工具鏈整合**
	- 使用 LangChain 的 SimilaritySearch 搭配 MMR 機制
		- 或使用 TimeWeightedVectorStoreRetriever
		- 考慮 LlamaIndex (GPT Index) 的組合索引（Composed Index）
		- 同時包含向量索引和關鍵詞索引，實現智能檢索調度

## 二、穩健的跨文檔比較表格生成方法

### 1\. 結構化信息自動萃取

- **利用 LLM 提取**
	- 使用 OpenAI GPT-4 的理解能力
		- 結合函數調用或提示模板
		- 從每份文件中抽取關鍵字段及取值
		- 輸出為 JSON 等結構化格式
- **提取範例**
	- 技術規格書： `{"產品名稱": "...", "尺寸": "...", "重量": "...", ...}`
		- 合同條款： `{"合同名稱": "...", "付款條款": "...", "違約責任": "..."}`

### 2\. 統一字段名稱與識別差異

- **字段歸一化**
	- 識別不同措辭的相似屬性（如"電池壽命" vs "續航時間"）
		- 建立同義詞映射表
		- 使用 GPT 根據語義判斷字段等價性
		- 利用向量嵌入進行字段名稱相似度匹配
- **處理缺失值**
	- 對於缺少的屬性記為"N/A"或空白
		- 確保最終表格涵蓋所有重要信息
		- 清晰展示異同

### 3\. 自動生成動態比較表格

- **表格生成策略**
	- 使用 GPT 生成 Markdown 表格或 HTML 表格
		- 根據比較項變化自適應調整表格列
		- 讓 GPT 輸出機器可讀格式（如 JSON 列表）
		- 再由程序渲染成表格
- **技術實現**
	- 借助 LangChain 的 OutputParser 要求 JSON 格式輸出
		- 使用 Python 庫（如 Pandas）或前端代碼構造表格
		- 通過程序邏輯保證表格的正確性和一致性

### 4\. 保持文檔來源清晰

- **來源標識**
	- 在每個文檔內容前添加標籤（如"《文件A》:"）
		- 在抽取信息後附上來源文檔名
		- 在 GPT-4 上下文中加入明顯的來源標記
- **技術支持**
	- 利用 LangChain 或 LlamaIndex 的元數據功能
		- 在 chunk 元數據裡存儲文檔標識
		- 在構造提示時自動包含這些標識
		- 防止模型混淆不同文件的數據

### 5\. 流程自動化實現

- **LangChain 整合**
	- 構建多步 Chain：提取鏈（Mapping）+ 格式化鏈（Reduction）
		- 支持工具調用，讓 GPT 調用自定義函數
		- 輔助表格生成或數據合並
- **LlamaIndex 應用**
	- 建立索引進行跨文檔查詢和總結
		- 結合 Graph Store 表示文檔間關聯
		- 表示字段對齊關係

## 三、技術方案總結

### 系統架構優勢

1. **檢索階段** ：採用智能索引與排序策略，提高相關文檔召回率和精度
2. **處理階段** ：運用 LLM 輔助的結構化抽取和智能表格生成
3. **比較階段** ：實現跨文檔信息的對齊比較

### 技術棧整合

- **核心 API** ：OpenAI API（嵌入和生成能力）
- **工具鏈** ：LangChain、LlamaIndex 等生態工具
- **數據庫** ：向量數據庫（Pinecone、Weaviate、Redis等）

### 預期效果

- 有效避免關鍵文件的遺漏和錯誤引用
- 提升回答的完整性和準確性
- 使多文檔比較分析變得高效而可靠
- 更好地勝任處理技術規格、合約條款等複雜場景的需求

通過更精確的檢索和穩健的表格輸出，RAG 系統將大幅提升處理複雜文檔分析任務的能力。
