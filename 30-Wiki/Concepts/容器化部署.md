# 容器化部署

## 核心定義
容器化部署（Containerized Deployment）是將應用程式及其所有相依環境打包為容器映像（Container Image），並以容器實例形式在任意環境中一致運行的部署模式。在 ML 工程場景中，容器化解決了「在我電腦上可以跑」的環境一致性問題。

## 運作原理

### 核心概念層次
```
硬體（GPU / CPU）
    ↑
Container Runtime（Docker / containerd）
    ↑
Container Image（Dockerfile 建置）
    ↑
應用程式（Python / TensorRT / Web Service）
```

### ML 模型容器化要點

#### GPU 支援
```bash
# 啟動含 GPU 的容器
docker run --gpus all --runtime nvidia nvidia/cuda:11.8-base nvidia-smi

# docker-compose 方式
services:
  inference:
    image: myapp:latest
    deploy:
      resources:
        reservations:
          devices:
            - capabilities: [gpu]
```

#### 多平台部署（Jetson / x86 共存）
```bash
# 建置 arm64 映像
docker buildx build --platform linux/arm64 -t myapp:arm64 .
# 建置 amd64 映像
docker buildx build --platform linux/amd64 -t myapp:amd64 .
# 合併 manifest
docker manifest create myapp:latest myapp:amd64 myapp:arm64
docker manifest push myapp:latest
```

### 與直接部署的比較
| 面向 | 容器化部署 | 直接安裝 |
|------|-----------|---------|
| 環境一致性 | ✅ 完全隔離 | ❌ 因機器而異 |
| 部署速度 | ✅ `docker pull && run` | ❌ 需逐步安裝 |
| 版本管理 | ✅ Image tag | ❌ 手動紀錄 |
| 除錯難度 | 稍高（需進容器）| 較直接 |
| 資源開銷 | 輕量（vs VM）| 最輕 |

## 優點與限制
- **優點**：環境一致性；快速水平擴展；版本回滾容易
- **限制**：GPU 支援需要 NVIDIA Container Toolkit；ARM 交叉編譯效能有限
