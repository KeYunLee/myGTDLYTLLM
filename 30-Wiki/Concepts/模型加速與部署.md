# 模型加速與部署

## 核心定義
模型加速與部署（Model Acceleration & Deployment）是將訓練完成的 AI 模型在生產環境中高效運行的工程實踐，核心目標是在滿足延遲（Latency）與吞吐量（Throughput）要求的前提下，降低計算資源消耗。

## 運作原理

### 主流部署路徑
```
訓練框架（PyTorch/TensorFlow）
    ↓ 模型序列化（.pt/.h5/.pb）
    ↓ 轉 ONNX（中間格式，跨框架）
    ↓ 轉 TensorRT（NVIDIA GPU 最佳化）
    ↓ 容器化（Docker）+ 服務化（gunicorn/uvicorn）
    ↓ 邊緣部署（Jetson / x86 Server）
```

### 關鍵工具鏈

| 工具 | 職責 |
|------|------|
| ONNX | 模型中間格式，跨框架橋樑 |
| TensorRT | NVIDIA GPU 推論優化引擎 |
| trtexec | 命令列 ONNX → TRT 轉換工具 |
| netron | ONNX 模型視覺化 |
| Docker + buildx | 跨平台容器打包（x86/ARM） |
| gunicorn + uvicorn | Python ASGI/WSGI 服務 |

### 邊緣 vs 雲端部署
| 環境 | 硬體 | 框架 |
|------|------|------|
| 雲端/本地 Server | x86 NVIDIA GPU | TensorRT 8.0+ |
| 邊緣（Jetson NX/Nano） | ARM + CUDA | Jetpack + TensorRT |
| 多平台統一部署 | x86/ARM | Docker Manifest + buildx |

### 精度/速度 Trade-off
- FP32：基準精度，速度最慢
- **FP16**：精度損失極小，速度提升顯著 ★生產推薦
- INT8：精度有損，需 calibration dataset，速度最快

## 優點與限制
- **優點**：TRT 加速顯著（2-5x）；Docker 確保環境一致性
- **限制**：`.trt` 平台綁定；轉換流程複雜；調試困難
